Implementing Player Identity in SwiftUI

Use native controls only (Button, Toggle, Picker, Menu, TextField, Table/List, ProgressView, .sheet, .popover, .confirmationDialog/.alert, Settings scene). The HTML is a visual spec: where it draws a control, use the matching system control and keep the spacing, type and colours below. No third-party packages.

tokens.cssEvery token (type, spacing, radii, light + dark colours). Single source of truth. icons.jsSVG stand-ins. Each carries data-sf-symbol; use Image(systemName:). MainWindow.dc.htmlMain window. 2 · Windows & structure

  • Main: WindowGroup, .defaultSize(900×760), .frame(minWidth: 720, minHeight: 520), .windowToolbarStyle(.unified). Toolbar: status (principal/leading), Refresh (⌘R) and Save (⌘S) as ToolbarItems with .help() tooltips and .keyboardShortcut.
  • Below the toolbar: optional update banner (not scrolled), then a ScrollView with 16 pt padding: [Profile | Network] row (Grid, 1.38 : 1), Servers card, Reasons card. At widths < 820 pt the top row stacks (ViewThatFits).
  • Settings: Settings { TabView { General, Updates } } at 600×520, each tab a ScrollView of grouped cards (Form .formStyle(.grouped) is acceptable if it matches the card spec).
  • No custom window chrome. Traffic lights, title bar and tab toolbar in the mockups are the system ones.

5 · Colour tokens

Create one Asset Catalog Color Set per token with Any + Dark appearances. Brand slate #1B2432 is the dark card surface and light-mode ink; teal #2FB6A8 is the accent (AccentColor). Text-on-surface uses the “-text” variants, which pass WCAG AA (≥ 4.5 : 1); raw status colours are for icons and fills only. Status is never conveyed by colour alone — every icon has a text label beside it.

9 · Accessibility & keyboard order

  1. Toolbar: Refresh → Save (status is an accessibility element with label + value, announced on change).
  2. Update banner (if shown): Release Notes → Update Now → Dismiss.
  3. Profile: Name combo box → Model menu → copy/reveal buttons (top to bottom) → Apply….
  4. Network: Copy public IP → (Retry, in error).
  5. Servers: filter chips (Banned, Favourites, Watched) → search → filter options → Add Server → table. In the table, ↑/↓ moves rows; within a row Tab goes star → bell → Fix….
  6. Reasons: All Actions → each reason’s action button.
  7. Sheets trap focus; Return = default (Apply/Export/Import), Esc = Cancel. Destructive alerts make Cancel the default; the destructive button never responds to Return.

Toggle buttons (star, bell, chips) expose isSelected traits and labels like “Add to Favourites”. All text meets AA in both appearances; disabled controls use system disabled styling (≈ 45 % opacity) and carry an explanatory note nearby.

10 · Localisation & truncation

  • Strings live in a String Catalog (en, tr). Turkish runs ~20–35 % longer; no fixed-width text containers except table columns, which truncate with tooltips.
  • Don’t use .textCase(.uppercase) — Turkish dotted/dotless i (i/İ, ı/I) breaks. Group and column headers are sentence case.
  • Use locale formatting: “13.4 MB” / “13,4 MB”, “62 %” / “%62”, dates “3 Nov 2026” / “3 Kas 2026”.
  • CIDs (32 hex) and paths: .lineLimit(1).truncationMode(.middle) + .help(fullValue) + .textSelection(.enabled). In tables the CID shows 8…8 (e.g. 9f3a1c7e…d7b8a4e2) in a fixed 150 pt column.
  • Host → IP: the host truncates (tail), the IP:port never truncates. Server names truncate tail.
  • Rows never jump: fixed row heights, fixed column widths, monospaced digits, and a reserved slot for the Fix… button column.

11 · SF Symbols used

The drawings are approximations — always use the real symbol by name. Fill variants use .symbolRenderingMode(.hierarchical) or .palette with white glyph on status colours.
